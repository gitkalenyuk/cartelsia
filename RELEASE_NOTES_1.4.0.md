# Cartelsia 1.4.0 — Автореєстрація + Catch-All

## Що це

Автоматичне створення десятків акаунтів Cartesia в один клік: софт сам генерує `cartelia_<rand>@kaleny.uk` + пароль, проходить форму на `play.cartesia.ai/sign-in/create`, чекає OTP через **catch-all пошту** по IMAP, вводить код, створює API-ключ на `/keys` і **одразу додає його в пул** (`keys.json`) + у `accounts.txt`. Ключі — 20 000 символів/міс кожен, ліміт 2 одночасних запити на ключ.

Якщо капча Turnstile — відкривається окреме вікно Chromium, клікаєш галочку вручну і тицяєш «Готово». За бажанням — автосолвер через **2captcha / CapSolver** (налаштування в Налаштуваннях).

## Що нового в 1.4.0

| Кейс | Було | Стало |
|---|---|---|
| **Брати OTP для правильного @kaleny.uk** | Брався останній код з ящика | **Строго по `TO` заголовку** (`To/Delivered-To/Envelope-To`) — кожен акк отримує *свій* код |
| **`Incorrect code` → сторінка пропадала** | Робився `page.goto/reload`, OTP-поле зникало | **Ніякого reload**: поле лишається, код чиститься і чекаємо новий лист з іншим OTP (до 90 с) |
| **Очікування листа** | 3 с / fallback на весь INBOX | **Кожні 5 с**, лог `still waiting …s`, 20 UID, розбір `quoted-printable/base64`, `servername` для IMAP TLS |
| **Створення ключа** | 1 шлях `Enter` | **3 стратегії**: `Enter` → клік Submit у діалозі → `Enter` на `form`, сканування `innerHTML + clipboard` |
| **Прогрес** | «Триває…» без деталей | **Жива таблиця**: Email · Статус (badge) · Ключ (маскований, копі) · Помилка, прогрес-бар, кнопка **Зупинити** |
| **Черга** | Блокуючий `for` + `pool.addKeys` без `await` | **`AutoregService`** з подіями `autoreg-progress/done/item-done`, `await pool.addKeys`, відновлення стану при перемиканні вкладок |
| **Налаштування** | Лише `catchAllDomain + IMAP` | Додав **captchaProvider (manual/2captcha/CapSolver)**, API-ключ, **паузу між акаунтами**, **режим Chromium** (bundled vs докачка) |
| **Chromium** | Падіння без `Executable doesn't exist` | Авторезолв шляху + `npx playwright install chromium` fallback |

```

        ↓
[Браузер → Авторег] обираєш N (1–50) → Запустити
        ↓
AutoregService (main):
  для кожного cartelia_<time>_<rand>@kaleny.uk
    ├─ Chromium: goto /sign-in/create → fill 4 інпути → Continue
    ├─ чекає /verify-email-address + OTP-інпути (60 с)
    ├─ IMAP: кожні 5 с питає лист СТРОГО для цього TO → витягує <b>######</b>
    ├─ вводить OTP (data-input-otp / one-time-code), Enter
    ├─ якщо Incorrect code → чистить поля → чекає новий OTP → другий ввод
    ├─ goto /keys → Create API key → заповнює description 3 шляхами → poll sk_car_ 90 с
    └─ pool.addKeys([sk_car_...]) + accounts.txt (data/ + output/)
  з паузою 2–6 с між акаунтами
        ↓
[Таблиця в Браузері] живе оновлення, капча-блок, копі пароля/ключа, авторефреш ключів
```

## Налаштування — що і де брати

### Catch-All домен (`kaleny.uk`)
- Це домен, де **всі** листи на `*@kaleny.uk` падають на одну головну пошту (в тебе — `nameofsewar@gmail.com`).
- Як підняти свій: у реєстратора домену / поштового хостингу включи Catch-All Forwarding (наприклад, Cloudflare Email Routing → уловлює `@yourdomain.com` → forward → твій Gmail). Без власного домену можна взяти готовий catch-all поштовий сервіс.

### Gmail IMAP
- В Налаштуваннях → **Автореєстрація & Catch-All пошта**: вкажи `catchAllDomain`, `IMAP Сервер` (`imap.gmail.com:993`), логін і **App Password** (не звичайний пароль).
- Де взяти App Password: https://myaccount.google.com/apppasswords → обери «Пошта» → «Інший» → скопіюй 16 символів типу `kvti mrvs iqmr wufe`.
- Потрібен увімкнений 2-step verification на акаунті.
- Кнопка **«Перевірити підключення IMAP»** тестує `LOGIN + SELECT INBOX` перед авторегом.

### Капча (Налаштування → Налаштування автореєстрації)
- **Ручна** (за замовчуванням): відкривається Chromium, клікаєш галочку Turnstile → «Готово, продовжити».
- **2captcha / CapSolver**: введи свій `captchaApiKey`, провайдер підставиться в чергу (MVP — поки fallback у ручний; автосолвінг робиться через `challenges.cloudflare.com/turnstile` токен).

### Пауза між акаунтами
- Поле «Пауза між акаунтами (мс)» — рандомізовані затримки, рекомендовано 2000–6000, щоб не тригерити антифрод WorkOS.

### Режим Chromium
- **Докачка при першому запуску** (за замовчуванням, легший .exe) / **Все в .exe (офлайн, ~150 МБ)** — впливає лише на пакування (див. `electron-builder.yml`).

## Вкладка Браузер — як користуватись
- Вгорі: лічильник `Кількість акаунтів: 1–50` → **Запустити (N акаунтів)**. Якщо авторег уже йде — кнопка міняється на **Зупинити**.
- Під час авторегу — **прогрес-бар** і лічильник `+N ключів у пулі`.
- Якщо Turnstile — жовтий банер із `Готово, продовжити / Скасувати` (оверлей для `autoreg-captcha`).
- Нижче — **таблиця результатів**: кожен акк — бейдж статусу (`У черзі / Форма… / Чекаю листа… / Верифікація… / Створюю ключ… / Готово / Помилка / Скасовано`) + маскований `sk_car_…XXXX` + кнопка копі, іконки копі email/пароля.
- `accounts.txt` пишеться двічі: `data/accounts.txt` (поряд із `keys.json`) і `output/accounts.txt` (експорт). Формат: `YYYY-MM-DD HH:MM:SS | Email: ... | Pass: ... | Key: ... | ok|error`.
- `keys.json` одразу пополняється — вкладка **Ключі** показує `+N` без перезапуску.

## Обмеження та поради
- **WorkOS + IP**: великі пачки (20–50) з одного IP можуть упіймати rate-limit — тримай паузи 3–6 с і роби пачками по 10.
- **Shadow DOM Turnstile**: `hasCaptcha` тепер дивиться в shadowRoot, але Cloudflare може міняти DOM — ручний режим завжди бекап.
- **Лист не прийшов** за 3 хв — акк позначається `Лист підтвердження не прийшов` і пропускається, решта черги йде далі.
- **Не оновлюй вкладку verify вручну** — бот сам дочекається листа і введе код; ручний рефреш скине стан.
