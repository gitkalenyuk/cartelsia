# Cartelsia 2.1.0 — Спільні голоси + кеш TTS

**Дата:** 27.08.2026

## Суть релізу

Будь-який публічний («Shared») голос Cartesia можна додати за Voice ID під зрозумілим
імʼям — і озвучувати ним **усім пулом безкоштовних ключів**. Кредити при цьому
списуються з вашого ключа, який робить запит, а не з акаунта власника голосу.

Сценарій: 100 000 символів тексту на пулі з 5 ключів по 20 000 → текст розбивається
на фрагменти, кожен фрагмент іде на свій ключ, але ВСІ озвучені одним обраним голосом.

## Факт (перевірено наживо 27.08.2026)

- `GET /voices/{id}` ключем БЕЗ доступу до чужого ПУБЛІЧНОГО голосу → 200,
  `is_owner: false`, `access: {type: "public"}` ✅
- `POST /tts/bytes` тим самим чужим free-ключем із цим voice_id → справжні WAV-байти ✅
- Кнопка **Share → Shared** у play.cartesia.ai = `access.type: "public"`; значень
  «organization»/«shared» у API немає — тільки private/public.
- Скопіювати/імпортувати чужий голос у свою бібліотеку НЕМОЖЛИВО — такого endpoint
  не існує. Тому реєстр аліасів зберігається ЛОКАЛЬНО (`data/shared_voices.json`),
  нічого в Cartesia не пишеться.
- PVC (Pro Voice Clones): сумісні моделі в `fine_tunes[].public_model_id`;
  невідповідна модель → 400 `voice_model_mismatch`.

## Що зроблено

### 🌐 Реєстр спільних голосів (Клон голосу → Спільні голоси)
- Поле Voice ID + аліас (`[a-z0-9-]`, 2–40 символів, унікальний).
- Валідація форми UUID до мережі; далі GET /voices/{id}:
  - 404 → «Голос не знайдено: приватний або ID хибний»;
  - 401/403 → «Ключ відхилено або голос недоступний»;
  - **приватний чужий → відмова додавання** (не зберігаємо непридатний запис).
- Для PVC одразу запамʼятовується список сумісних моделей.
- Зберігається: alias, voice_id, remote_name, language, is_owner, access, is_pro,
  added_at, last_verified, status (ok/revoked/unreachable).
- Кнопки на рядку: прослухати семпл · «Використати голос» · видалити (тільки локальний запис).

### 🛡️ Захист від ревокації (важливо для чужих голосів)
Власник може вимкнути Share будь-якої миті без попередження. Тому:
- Перед КОЖНИМ стартом генерації зі спільним голосом scheduler робить свіжий
  GET /voices/{id} (кеш last_verified тут не аргумент).
- Якщо голос став приватним/недосяжним → прогір ЧЕСНО зупиняється: чанки
  позначаються failed із поясненням, тост називає аліас і причину.
- **Ніколи не мовчки підмінюємо іншим голосом** — відео з чужим голосом гірше за впалий рендер.
- Ручна кнопка «Перевірити всі» оновлює статуси всього реєстру.

### 💾 Кеш TTS (`data/tts-cache/`)
- Ключ: sha256(voice_id | model_id | language | text) → шлях `ab/<hash>.wav`.
- Хіт (>44 байт) повертається миттєво, без API і без списання кредитів —
  переозвучки/правки одного абзацу більше не коштують ні копійки.
- Атомарний запис: `.tmp` → rename; crash ніколи не лишає обріаний «живий» файл.
- Субтитр-режим (word timestamps) не кешується. У версії чанка видно мітку «· кеш».

### 🔗 Інтеграція
- Спільні голоси зʼявляються у VoicePicker композера секцією «🌐 Спільні голоси» з бейджем @аліас.
- Вибір такого голосу НЕ пінгує ключ-власник (він не потрібен) і ставить sharedVoiceAlias
  у налаштуваннях чату — саме він тригерить пребатч-гейт.
- Видалення клона з реєстру НІКОЛИ не викликає DELETE на Cartesia (ми ним не володіємо).
